# Related Objects section: UI test log

Component: `templateRelatedObjects` (2,045 lines JS, 309 lines HTML). Org: scratch org `dxtemplates-scratch-30d`, template "ZZ Clip Test", section "RO Opps" (Opportunity under Account). Same method as the Table and Context logs. Jest baseline before this round: 9 tests.

Where it is stored: the whole configuration is JSON in `Section_Content__c` of the section record (not `Section_Details__c`, which stays empty). The PDF builds the table and chart on the server from this JSON and live data, so the saved record has no HTML to inspect.

| R-D14 | **Renaming the header of the chart field broke the chart.** The chart finds its column with `tableheaders.indexOf(selGraphvalue)`, i.e. by comparing the saved chart field text with the saved header text. Renaming a header (tick next to the header) updated the field list but not the Sub Total pill, the chart field list or the chosen chart field, so after a save the chart field matched no header and the PDF chart drew NaN. | Renaming a header now renames the pill, the chart field list entry and the chosen chart field (and cancelling the rename reverts them): `renameSubtotalLabel`. | Jest ("keeps the chart pointing at its column when the header of the chart field is renamed") failed first on the saved chart field. Browser: renamed "Amount" to "Amount Net"; the pill followed; the saved labels and `selGraphvalue` both hold "Amount Net"; the Preview chart shows the axis label "Amount Net" and the shares 54, 21, 12, 8, 3, 3 per cent. |

"The first Save click is ignored" (U-R14, second part) was not an application defect. When it happened again, a click logger showed that no click reached the Save button: the browser window had become taller, so the button was below the visible area and the click landed on a chart bar. The earlier misses were the half-loaded section (R-D9) or the same stale click position. With correct positions the first click saved every time (also after changing a dropdown). One real first-click behaviour remains: a table header only shows its tick and cross buttons after a second click on it (U-R16 below).

Left for the UI discussion (design questions, not defects): U-R1 (all objects listed as related objects), U-R3 (nothing says that a chart needs a Sub Total and a Category), U-R4 (the "Y%" and placeholder numbers in the sample chart), U-R8 (no value axis on the chart), U-R11 (filter dialog gives no feedback and only offers the section's own object), U-R12 (Delete without confirmation, all section types), U-R6 (long page), the parent field label "Account ID.Employees" (not changed: the chart finds its column by matching the chart field text with the table header text, so a new label would break the chart of existing sections), and the new observation that Integer cells print without decimals while their Sub Totals print with two.

The same coupling (the chart finds its column by comparing text) still exists in the PDF component: renaming a header on an already saved section and saving is now safe, but any other way of making the saved chart field differ from the saved headers would still draw NaN. Making the chart use the column's field name instead of its text would remove the coupling; not done, it needs a change of the saved JSON.
