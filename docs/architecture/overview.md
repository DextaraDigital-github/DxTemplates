# DxTemplates Architecture Overview

## 1. Why it exists

From the product deck (`DXTemplates Overview V1.3.pdf`, Aug 2024):

- Out-of-the-box Quote templates are inflexible.
- No built-in tool provides templates for all objects.
- Most AppExchange alternatives are paid.
- Teams want automated document generation.

DxTemplates is a Salesforce-native app (LWC, Apex, Visualforce, Flow) with three phases:

| Phase | What happens |
|---|---|
| Design time | An admin builds a template from dynamic sections with a click-not-code UI. |
| Run time | A user picks a template on a record and generates a PDF, saved as an Attachment. |
| Automation | Flow or Apex generates the PDF with no user and can email it. |

Other stated capabilities: works in Experience Cloud, e-sign integration, watermarks, clone with versions, import/export, conditional logic, multi-language, custom Flow/Apex tokens.

## 2. Data model

| Object | Purpose |
|---|---|
| `Document_Template__c` | A template. Related object (`Related_To_Type__c`), version, active flag, page/header/footer/watermark settings as JSON in `PDF_Page_Properties__c`, optional Apex class (`ClassId__c`) or Flow (`FlowId__c`) for custom merge data. |
| `Document_Template_Section__c` | One ordered section. `Type__c` is Header, Footer, Context, Clause, Table, Related Objects, Custom or Inner Section. `Section_Content__c` holds HTML or JSON. Optional visibility rule. |
| `Document__c` | A generated document. A parent record (sequence -1) plus child records holding the body in 100,000-character chunks, linked by `External_Id__c`. |
| `Rule__c`, `Rule_Condition__c` | Conditions that decide whether a section is shown. |
| `Document_Clause__c` | Reusable clause text. |
| `Translator__c` | Per-language translated values. |
| `TransactionLog__c` | Error and info log written by `LogHandler`. |

Custom metadata: `DxTemplates_VF_Style__mdt` (PDF CSS), `ChartAutomationStyleResources__mdt`, `DxTemplates_PDFLink__mdt` (help links), `DXTemplates_HandlerClass__mdt` (handler class name), `Document_Translation__mdt`.

## 3. Section types

| Type | Content | Rendered from |
|---|---|---|
| Header, Footer | Rich text columns | JSON in section content |
| Context | Rich text with merge fields | `MergeFieldsClass` replaces tokens with record values |
| Clause | Text from a `Document_Clause__c` | Clause body |
| Table (static) | Fixed rows and columns, per-cell rich text, merge/remove cells | Built in the browser, no query. Editor: `templateTableDetails` |
| Related Objects | Rows from a child-object SOQL query, grouping, subtotals, optional chart | `DisplayRelatedObjects`, `ROsectionAutomationController` |

## 4. How a PDF is produced

1. User opens a record page that has the `DXTemplates PDF Generator` component (`dxtemplateSelectorCmp`). This component is not on any page after install; an admin adds it in Lightning App Builder.
2. The component lists active templates (`IsActive__c = true`) for the record's object.
3. `DisplayPDFController.getTemplateSections` loads sections, evaluates visibility rules, runs the optional handler class (`DXHandlerInterface.execute`) or Flow, and `MergeFieldsClass.mergefieldsMethod` substitutes record values.
4. The merged HTML is saved as `Document__c` records (chunked).
5. The Visualforce page `renderAsPdfLWC` (controller `DisplayPDFController`) applies page size, orientation, header/footer, watermark and CSS, then `getContentAsPDF()` produces the PDF.
6. The PDF is stored as an Attachment on the `Document__c` parent and shown or saved.

Automation path: Flow action `documentAutomationController.autoGenerateDocumentRecord` generates the `Document__c` records and enqueues `sendEmailAutomation` (Queueable, callouts allowed) to render the PDF and email it.

## 5. LWC component map

Verified from the `<c-...>` tags in each template (commit `b99ae1f`).

```
dxTemplateSetup (DXTemplates tab: list, import/export, watermark)
 ├─ menuSetup → menuSetupRow → summaryChildHierarchy (recursive)
 ├─ searchCategory
 ├─ modal
 └─ templateDesignerCMP (the designer)
     ├─ templateHeader → templateHeaderType → dxLookupFieldsDisplaycmp, modal
     ├─ templateFooter → templateFooterType → dxLookupFieldsDisplaycmp, modal
     ├─ templateContentDetails (Context/Clause) → conditioncmp, dxLookupFieldsDisplaycmp,
     │                                            imageResizeCMP, modal, multiLookupComponent
     ├─ templateTableDetails (static Table) → conditioncmp, dxLookupFieldsDisplaycmp, modal
     ├─ templateRelatedObjects → conditioncmp, hiddenComponent, modal, searchCategory
     ├─ cloneDocumentCmp, dxShowSelectedTemplate (preview), multiLookupComponent,
     │  dxLookupFieldsDisplaycmp, searchCategory, modal

dxtemplateSelectorCmp (end-user "PDF Generator")
 ├─ dxShowSelectedTemplate → displayRelatedObjectsData, modal
 └─ multiLookupComponent
dxSelectedRelatedObjectTemplateCmp → dxShowSelectedTemplate, multiLookupComponent
conditioncmp → conditionRowcmp           (shared helper: conditionUtil)
generatePDF, transalatorLWC               (standalone)
```

Apex classes called from LWC (import count): `SaveDocumentTemplatesection` 19, `RelatedObjectsClass` 15, `SaveDocumentTemplate` 12, `LogHandler` 10, `ImportExportData` 10, `LanguageTranslatorClass` 9, `FooterClass` 9, `DisplayPDFController` 8, `ScreenshotController` 6, `PdfDisplay` 6, `PopUpMessageSelector` 5, `ProductSetupCtrl` 3, `MergeFieldsClass` 2, `MultiSelectLookupController` 1, `DisplayRelatedObjects` 1.

Component communication is by `CustomEvent` bubbling up the tree (`datasaved` is dispatched 36 times) and `@api` properties down. There is no Lightning Message Service or shared store.

## 6. Packaging

`sfdx-project.json` defines four package directories that all point at `force-app`: `DxTemplates_Unlocked`, `Dx_Templates`, `DxTemplates_ManagedPackage`, and `DxTemplates_Managed_v3` (default, namespace `DxCPQ`, source API 61.0). `PostInstallDataCreation` seeds sample templates from the static resource `TemplatesAndSectionData` and schedules a monthly `AttachmentDeletionBatch`.

## 7. Known gaps in this document

- The Apex classes were read at method level only, not line by line.
- Rule evaluation and the Table-in-Table reference (`MergeFieldsClass`, section lookup by name) are described from a single query and not confirmed by a close read.
- Experience Cloud behaviour is stated by the product deck and has not been tested.
